# UI i18n guide (R16 of gauntlet)

YouFace ships with a tiny, zero-dependency i18n module at
`frontend/src/i18n/`. It supports **English** and **Brazilian
Portuguese** out of the box, with a `<LocalePicker />` component that
lets users switch language from the cockpit header.

## Usage in components

```tsx
import { useLocale } from "../i18n";

export function MyComponent() {
  const { t, locale } = useLocale();
  return <button>{t("action.save")}</button>;
}
```

`t(key, values?)` returns the active translation. Missing keys fall
back to English, then to the literal key (so you can grep for
untranslated strings).

## Adding a new string

1. Add the key to `frontend/src/i18n/locales/en.ts` (the source of truth).
2. Add the same key + translation to all other locale files.
3. Use `t("your.key")` in components.

## Adding a new language

1. Copy `frontend/src/i18n/locales/en.ts` to `frontend/src/i18n/locales/<code>.ts`.
2. Translate every value. Keep the keys identical.
3. Register the locale in `frontend/src/i18n/index.ts`:
   ```ts
   import es from "./locales/es";
   const TRANSLATIONS = {
     "en": en,
     "pt-BR": pt,
     "es": es,
   } as const;

   export type LocaleCode = "en" | "pt-BR" | "es";

   export const SUPPORTED_LOCALES = [
     { code: "en", label: "English" },
     { code: "pt-BR", label: "Português (Brasil)" },
     { code: "es", label: "Español" },
   ];
   ```
4. Update `detectInitialLocale()` if you want browser language
   detection for the new locale.

## Locale persistence

The active locale is persisted in `localStorage` under
`youface.locale`. On first load, the hook picks:

1. The stored value (if present).
2. The browser's `navigator.language` (prefix-matched: `pt*` → `pt-BR`).
3. The default (`en`).

## When NOT to use this module

- **Server-side rendering**: this module assumes `window.localStorage` is
  available. The hook runs only on the client (wrapped in `useEffect`).
- **ICU plurals / gendered strings / RTL**: not yet supported. For those,
  consider migrating to `next-intl`.

## Roadmap

- Auto-detect from `Accept-Language` header server-side (would let the
  frontend hydrate with the right locale on first render).
- Lazy-load locale chunks (`React.lazy` on the locale files) once we
  exceed ~4 languages.
- Migrate to `next-intl` if ICU features become necessary.
